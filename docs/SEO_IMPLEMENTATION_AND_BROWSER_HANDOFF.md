## What is already implemented

### Canonicals and host normalization

- Every main public page declares a canonical URL.
- Canonicals are resolved against `NEXT_PUBLIC_SITE_URL` or the Vercel production URL.
- The production canonical origin is `https://owmotorsport.com`.
- Live verification on 24 October 2026 showed:
  - `https://owmotorsport.com/` returns `200 OK`.
  - `https://www.owmotorsport.com/` returns a `307` redirect to `https://owmotorsport.com/`.
- Filtered catalogue URLs canonicalize to the unfiltered landing page and receive `noindex, follow`.
- Valid paginated catalogue pages after page 1 are indexable and self-canonicalize with `?page=N`.
- Invalid page numbers, empty result pages, missing products, and error pages are no-indexed.
- Confirmed legacy product URLs permanently redirect to their exact current canonical products:
  - `/catalogue/lifan-k19` → `/motorcycles/lifan/lifan-k19`
  - `/catalogue/taro-c6` → `/motorcycles/taro/taro-c6`
  - `/catalogue/lifan-ss2` → `/motorcycles/lifan/lifan-ss-2`
- Legacy X-PECT and KPS 250 URLs intentionally remain `404` because those motorcycles do not currently have published canonical product pages in the production sitemap.
- `/favicon.ico` permanently redirects to the active application icon at `/icon.png`.

### Titles and descriptions

- All main public routes provide explicit metadata.
- Product titles and descriptions use database SEO fields when supplied.
- Product fallback title format is based on brand and model.
- Brand and category pages use their database SEO title/description when supplied.
- Blog articles use article-specific SEO title/description when supplied.
- The root title is `OW Motors | Multi-Brand Motorcycle Dealership`.
- The product title currently observed for Taro C6 is `Taro C6 Price and Specifications in Pakistan`.

### Social previews

- Open Graph metadata is generated for normal pages.
- Twitter/X card metadata is generated.
- Pages with an image use `summary_large_image`; otherwise they use `summary`.
- Product pages use the primary product image.
- Blog pages include article image, author, section, tags, publication date, and modification date.

### Structured data

Implemented JSON-LD types:

- `Organization`
- `WebSite`
- `Product`
- Multiple `Offer` nodes per product variant
- `BreadcrumbList`
- `FAQPage` on product pages when FAQs exist
- `Article` on blog article pages

Product offers include:

- Price in PKR
- Availability mapping
- New-condition status
- Canonical product URL
- Product/offer relationships

JSON-LD is escaped before insertion to prevent markup injection.

### Crawl controls

Production `robots.txt` currently allows public crawling and blocks:

- `/admin`
- `/admin/`
- `/api/`

It declares:

`Sitemap: https://owmotorsport.com/sitemap.xml`

Vercel preview deployments are globally no-indexed. Admin pages, login pages, error pages, and global errors are also no-indexed.

Live state verified on 24 October 2026:

- Category landing pages: 5

The sitemap includes `lastmod`, `changefreq`, and `priority`. Empty brand/category collections are excluded. Product and article changes feed their update timestamps into `lastmod`.

### Internal linking and semantic content

- Header and footer provide crawlable navigation.
- Brand, category, product, blog, about, and contact pages are internally linked.
- Product pages include visible breadcrumbs.
- Blog articles include visible and structured breadcrumbs.
- Product pages include related motorcycles and FAQs.
- Brand and category pages provide dedicated crawlable landing URLs.
- A skip link and semantic heading structure are implemented.

### Search-engine-facing rendering

- Metadata is forced into the initial HTML head for limited/HTML-only bots through the Next.js `htmlLimitedBots` setting.
- Public content is server-rendered, so crawlers do not depend on client-side JavaScript to discover core text and links.
- Image elements carry alt text from database or application content.

## Known gaps and recommended priorities

### Priority 1: verify indexing rather than blindly request it

In Search Console:

1. Open **Indexing → Pages**.
2. Record the current indexed and not-indexed totals.
3. Open every exclusion reason and export or list the example URLs.
4. Classify each URL as expected or unexpected.
5. Inspect representative URLs from every template:
   - Homepage
   - `/brands`
   - `/motorcycles`
   - One brand page
   - One category page
   - One product page per brand
   - One blog article
6. Use **Test live URL** before requesting indexing.
7. Request indexing only for important valid URLs that are not indexed—not redirects, duplicates, filtered URLs, or deliberate no-index pages.

### Priority 2: confirm canonical consolidation

For the homepage and representative product pages, compare:

- User-declared canonical
- Google-selected canonical
- Final URL after redirects
- Sitemap URL

All should resolve to the non-`www`, HTTPS version without unnecessary query parameters.

Expected redirect behavior:

- `http://owmotorsport.com/...` → `https://owmotorsport.com/...`
- `https://www.owmotorsport.com/...` → `https://owmotorsport.com/...`

### Priority 3: improve organization/local-business schema

The current global schema contains `Organization` and `WebSite`, but it does not yet expose the complete dealership entity. Consider adding an appropriate `MotorcycleDealer` or `LocalBusiness` node with verified:

- Postal address
- Telephone numbers
- Opening hours
- Google Maps URL
- Social profile URLs through `sameAs`
- Logo and image

Do not add review or aggregate-rating schema unless the displayed reviews and ratings meet Google’s eligibility and source requirements.

### Priority 4: update global brand wording

`src/lib/constants/site.ts` currently describes Taro, Lifan, Hi-Speed, and Super Star but omits Fuego. Update the global description so all five active brands are represented naturally.

### Priority 5: validate rich results

Run representative pages through Google Rich Results Test:

- One product with multiple variants
- One blog article
- Homepage/site organization schema

Check for errors and warnings in Product, Offer, Breadcrumb, FAQ, and Article markup. Validate the rendered production HTML, not localhost.

### Priority 6: evaluate content quality and duplication

Many product fallback descriptions use the same sentence structure. Review indexed product pages for:

- Unique descriptions
- Useful model-specific overview copy
- Complete specifications
- Accurate image alt text
- Non-duplicated FAQs
- Clear Pakistan-specific price and availability language

Do not invent specifications, stock, reviews, warranties, or prices. Use published backend data and owner-confirmed information only.

### Priority 7: Core Web Vitals and image performance

Use PageSpeed Insights and Search Console Core Web Vitals for mobile and desktop. Test at minimum:

- Homepage
- Motorcycle catalogue
- Image-heavy product page
- Brands page
- Blog article

Focus on LCP, INP, CLS, responsive image sizing, above-the-fold image priority, and excessive image payloads.

## Browser-agent operating rules

- Work against `https://owmotorsport.com`, not localhost.
- Prefer non-`www` URLs in every report and submission.
- Never remove URLs, request temporary removals, alter Google Business Profile data, or change DNS/domain settings without explicit owner approval.
- Do not request indexing for redirects, filtered catalogue URLs, duplicate URLs, admin pages, API routes, or intentionally no-indexed pages.
- Do not fabricate ratings, reviews, product availability, business details, or keywords.
- Before recommending a code change, capture the exact affected URL, observed HTML/Google status, expected result, and evidence.
- Distinguish Search Console reporting lag from an actual technical fault.
- After any fix, use live inspection first, then request validation/indexing only where appropriate.
- Keep an audit log with date, URL, action, result, and follow-up date.

## Definition of success

- Every valuable canonical page is crawlable, returns `200`, and appears in the sitemap.
- Redirect and duplicate URLs are excluded for the correct reason.
- Google-selected canonicals match the non-`www` declared canonicals.
- Product and article schema contains no blocking errors.
- Titles and descriptions are unique, accurate, and aligned with search intent.
- Mobile performance is acceptable on key templates.
- Search Console shows no unexplained indexing or sitemap errors.
